# AeroSim data folder

All content here is **synthetic**. It is produced by `backend/scripts/generate_example_dataset.py` (`cd backend && python scripts/generate_example_dataset.py`) from the seeded demonstration fleet and its chronologically consistent synthetic history.

## templates/

One CSV per importable dataset with the exact column names the validator expects. The same files are downloadable inside the application (Settings & data → CSV templates). Import order for a new component instance: `flight_schedule` → `flight_actuals` (marks flights completed) → `flight_observations` (keyed by flight ID) → `inspection_findings` / `maintenance_records` → *Re-initialise twin*.

| Dataset | Required columns | Units / notes |
|---|---|---|
| flight_schedule | aircraft_id, flight_date, route_or_mission, duration_min | known before the flight; payload_fraction 0–1, expected_temperature_c °C, expected_environment ∈ benign/humid/marine/desert |
| flight_actuals | flight_id, duration_min | as-flown conditions; refused for already completed flights |
| flight_observations | component_id, flight_id, t_s | t_s s; load_kN; strain_microstrain µε; temperature_c °C; pressure_bar; vibration_g g RMS; flight must be completed; ≥ 10 samples |
| predicted_outputs | component_id, flight_id, t_s | same schema, externally predicted series |
| inspection_findings | component_id, inspection_date, method | measured_value in the quantity's unit: crack_length_m → mm, pit_depth_m → µm, wear_indicator → –, oxide_thickness_m → µm, creep_strain → % |
| maintenance_records | component_id, maintenance_date, activity | repair_or_replacement ∈ none/repair/replacement; damage_after_value in SI |
| operational_records | component_id, flight_date, duration_min | operating-history summary |
| material_properties | component_id, parameter, value | parameter must exist for the component's model |
| load_history | component_id, t_s, stress_mpa | rainflow-counted on import |

## example_dataset/

| File | Content and generation |
|---|---|
| `flight_schedule_AIRCRAFT-001.csv` | Scheduled information of all 15 flights (12 completed, 3 scheduled) of AIRCRAFT-001: three demonstration routes, planned duration, payload fraction U(0.55, 0.95), forecast temperature, expected environment (seed 2026). |
| `flight_actuals_AIRCRAFT-001.csv` | As-flown conditions of the 12 completed flights (deterministic perturbations of the schedule, seed 7000 + sequence). Importing it into the seeded database is refused because those flights are already completed — use it with a fresh aircraft. |
| `flight_observations_ENG-MOUNT-001.csv` | 30 s samples of load, strain, temperature and vibration for the first three completed flights of ENG-MOUNT-001, generated by its hidden reference model (k_L 1.12, k_T 1.05, k_V 0.92; σ 2.5 kN, 25 µε, 1.2 °C, 0.04 g; T bias +1.5 °C). 750 rows. |
| `inspection_findings.csv` | All 8 synthetic inspection records of the fleet history (UT crack measurements drawn from the hidden true state with σ 0.2–0.3 mm, EC pit depths σ 10 µm, bench leakage tests σ 0.02, one qualitative borescope, one negative FPI). |
| `maintenance_records.csv` | Crack disposition (no state change) and the HYD-ACT-001 seal replacement (W → 0.02). |
| `operational_records.csv` | One summary row per completed flight for ENG-MOUNT-001. |
| `material_properties.csv` | Two illustrative parameter overrides. |
| `load_history_ENG-MOUNT-001.csv` | Deterministic synthetic stress sequence 120 + 80 sin(2πt/120) + 25 sin(2πt/7) + N(0, 6) MPa over 600 s for rainflow demonstration (seed 7). |

Every record carries provenance `synthetic_demo` / `synthetic_ground_truth` when generated, and `uploaded` when re-imported through the CSV interface.
